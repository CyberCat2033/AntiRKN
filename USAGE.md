# Руководство пользователя AntiRKN

> [!NOTE]
> AntiRKN предназначен для администрирования ваших собственных серверов и изучения сетевых протоколов. Перед использованием прочитайте [отказ от ответственности](DISCLAIMER.md).

**AntiRKN** — приложение для Windows, Linux и Android, которое управляет вашими серверами Ubuntu по SSH: устанавливает и настраивает VLESS (через 3x-ui / Xray), AmneziaWG и TrustTunnel, ведёт список клиентов и собирает для каждого клиента профиль Mihomo.

> [!IMPORTANT]
> **AntiRKN — панель управления серверами, а не VPN-клиент.**
> Само приложение трафик не туннелирует. Готовый YAML-профиль импортируется в клиентское приложение на ядре Mihomo.

## 1. Принципы и безопасность

- **Без собственного сервера.** У AntiRKN нет своего облака и учётных записей. Приложение подключается к вашим серверам по SSH, к Google Drive — только если вы вошли в Google, к GitHub — для проверки новых версий приложения и серверных компонентов.
- **Локальное шифрование.** Серверы, клиенты, ключи и пароли хранятся в локальной базе SQLite в зашифрованном виде (AES-256-GCM). Ключ шифрования лежит в защищённом хранилище ОС.
- **Проверка ключа сервера.** При первом подключении приложение показывает отпечаток SHA-256 ключа сервера. После подтверждения ключ сохраняется. Если ключ потом изменится, подключение блокируется.
- **Задания на сервере.** Установку, обновления и изменение настроек выполняет служба `antirkn-runner` на сервере. Прогресс задания сохраняется на сервере, поэтому закрытие приложения или обрыв SSH его не прерывают. После сбоя задание продолжается с последней контрольной точки.

## 2. Первый запуск и настройки приложения

### 2.1. Навигация

У приложения три вкладки: **«Серверы»**, **«Клиенты»** и **«Настройки»**. На узком экране они внизу (`NavigationBar`), на широком — слева (`NavigationRail`).

При первом запуске открывается вкладка «Серверы» с подсказкой «Серверов пока нет». Сервер добавляется кнопкой **«+»** в правом верхнем углу (см. [3.2](#32-добавление-сервера)).

### 2.2. Раздел «Настройки»

Вверху раздела, в группе **«Мои данные»**, находится карточка **«Синхронизация»** с текущим статусом. Это единственный вход на страницу синхронизации (см. [7.1](#71-синхронизация-через-google-drive)). Карточки нет, если вход Google в этой сборке не поддерживается.

В группе **«Настройки приложения»**:

| Пункт | Что внутри |
| :--- | :--- |
| **«Интерфейс»** | «Тема»: «Системная», «Светлая», «Тёмная». «Язык интерфейса»: «Как в системе», «Русский», «English». Выбор хранится на этом устройстве. Где платформа поддерживает динамические цвета Material You, используются они. |
| **«Клиентские профили»** | «Базовый конфиг» — YAML-шаблон для профилей клиентов, и «Публикация в Google Drive» (см. [раздел 6](#6-профили-и-раздача)). |
| **«Резервные копии»** | Сохранение данных в зашифрованный файл и восстановление из него (см. [7.3](#73-резервные-копии)). |
| **«Обновления»** | Новые версии приложения (см. [2.3](#23-обновления-приложения)). |
| **«О приложении»** | «Назначение», «Лицензии» (GNU GPL v3.0 и компоненты с открытым кодом), «Отказ от ответственности», «Исходный код». Две последние ссылки открываются в браузере. |

Отдельной настройки анимаций нет: если в системе анимации отключены, приложение их не показывает.

### 2.3. Обновления приложения

Новые версии публикуются в GitHub Releases. Файл обновления подписан, перед установкой приложение проверяет подпись и контрольную сумму SHA-256. Если проверка не прошла, установка не начинается.

В **Настройки → «Обновления»**:

- **«Проверять новые версии»** — искать выпуски на GitHub при запуске и периодически;
- **«Предлагать обновления»** — показывать доступное обновление на главном экране;
- **«Проверить обновления»** — проверить сейчас.

Если вышла новая версия, видны размер и «Что нового», доступны кнопки **«Обновить»** и **«Пропустить версию»**. Установка зависит от формата:

- **Android** — откроется системный установщик. В первый раз Android попросит разрешить установку из этого источника: «Открыть настройки» → «Разрешить установку из этого источника» → вернуться и снова нажать «Установить»;
- **Windows** — запустится установщик, приложение закроется и откроется снова;
- **Linux, AppImage или архив** — файлы заменяются, приложение перезапускается;
- **портативная установка** — архив загружается, файлы в папке приложения заменяются вручную.

Если установку нельзя обновить из приложения, показывается ссылка «Страница выпуска».

## 3. Серверы

### 3.1. Требования к серверу

- ОС: **Ubuntu на x86_64**, версия не закреплена. Для других ОС и архитектур приложение подключение не продолжит;
- для службы заданий: работающий systemd 235+ и Python 3.8+ с модулем SQLite;
- учётная запись `root` или пользователь с `sudo`. Если `sudo` требует пароль, приложение спросит его и сохранит в зашифрованном виде. Политика `sudo`, требующая интерактивный терминал, не поддерживается;
- для установки компонентов: `ca-certificates` и свободное место на диске. Если чего-то не хватает, приложение сообщит об этом до начала установки.

### 3.2. Добавление сервера

1. На вкладке «Серверы» нажмите **«+»** («Добавить сервер»).
2. Заполните поля:
   - **«Имя сервера (необязательно)»**;
   - **«Адрес сервера»** — IP или доменное имя;
   - **«Порт SSH»**;
   - **«Пользователь SSH»**;
   - способ входа:
     - **«Пароль»**;
     - **«Приватный ключ»** — кнопка «Выбрать приватный ключ», файл без `.pub` (например, `id_ed25519`). Копия ключа сохраняется в зашифрованном хранилище. Если ключ защищён паролем, укажите «Passphrase ключа»;
     - **«SSH-agent Linux»** (только на Linux) — используются ключи из локального `ssh-agent`, приватный ключ остаётся у агента;
   - **«Jump SSH»** — «Прямое подключение» или подключение через другой сохранённый сервер.
3. Нажмите **«Сохранить и подключиться»**.
4. В окне «Проверьте подлинность сервера» сверьте отпечаток SHA-256 с доверенным источником, например с консолью хостинга, и нажмите **«Доверять и продолжить»**.

После подключения приложение читает с сервера ОС, адреса, состав установленного ПО и состояние служб. Позже данные подключения можно изменить на странице **«Доступ SSH»** кнопкой «Изменить подключение».

### 3.3. Страница сервера

Вверху страницы — кнопки **«Подключиться»** / **«Отключиться»**, **«Доступ SSH»** и счётчики «Протоколы», «Клиенты», «Обновления». Ниже:

- **«Протоколы»** — плитки VLESS, AmneziaWG и TrustTunnel с состоянием («Не установлен», «Не настроен», число подключений). Нажатие открывает страницу протокола (см. [раздел 4](#4-протоколы)).
- **«Обслуживание»**:
  - **«Обновления»** — компоненты сервера и пакеты Ubuntu (см. [3.5](#35-обновления-и-обслуживание));
  - **«О сервере»** — карточка «Выход в интернет» (см. [4.6](#46-выход-в-интернет-через-другой-сервер)), «Сервисный режим» (см. [3.6](#36-сервисный-режим)), «Публичные IP-адреса», «Трафик сервера», «Место на системном диске» и кнопка «Перезапустить сервер».
- **«Последние действия»** — история заданий на этом сервере со всех ваших устройств, по шагам. Полный список — «Показать все».

В «Трафик сервера» показан объём загрузки и выгрузки по интерфейсам с маршрутом по умолчанию с момента запуска сервера. Кнопка «Сбросить отсчёт» начинает отсчёт заново. Точка сброса хранится на этом устройстве.

Кнопка **«Диагностика IP»** в «Публичные IP-адреса» проверяет с этого устройства доступность публичных адресов сервера на указанном порту. Перед проверкой приложение предупреждает, что она может ненадолго нарушить связь устройства.

### 3.4. Защита SSH

Если вы подключены как `root`, на странице сервера появляется уведомление «Вход от root не защищён» с кнопкой **«Защитить сервер»**. Мастер:

1. создаёт пользователя с `sudo` и паролем (имя и пароль можно сгенерировать);
2. настраивает новый порт SSH (предлагается 2222) и UFW;
3. запускает таймер автоотката и проверяет вход нового пользователя на новом порту и права `sudo`;
4. после успешной проверки вы нажимаете **«Применить защиту»**, после чего прямой вход `root` отключается. Кнопка «Откатить изменения» возвращает прежние настройки.

Если у хостинга есть собственный сетевой фильтр (Cloud Firewall), откройте в нём новый порт до подтверждения.

### 3.5. Обновления и обслуживание

Страница **«Обслуживание» → «Обновления»**:

- компоненты сервера (3x-ui / Xray, AmneziaWG, TrustTunnel): «Проверить обновления», «Обновить», а также **«Версии»** — установка другой версии или возврат прежней. Новая версия ставится с проверкой реальных подключений. Если после обновления подключения перестали работать или устройство потеряло связь с сервером, сервер сам возвращает прежнюю версию. AmneziaWG собирается из исходного кода на сервере, поэтому установка занимает несколько минут;
- **Ubuntu**: список пакетов к обновлению, обновление индексов APT и пакетов. Если после обновления нужна перезагрузка, это показывается в карточке;
- **«Серверные задания»** — текущие и последние задания runner, отмена задания и сброс зависшей очереди.

Перезапуск сервера — кнопка **«Перезапустить сервер»** в «О сервере». После подтверждения приложение ждёт, пока сервер снова станет доступен.

### 3.6. Сервисный режим

Сервисный режим нужен на время проверки или ремонта сервера. Переключатель — в «О сервере» → **«Сервисный режим»** («Включить» / «Выключить»).

Пока режим включён:

- сервер продолжает работать, доступы клиентов на нём сохраняются;
- его узлы убираются из профилей клиентов, и следующая публикация проходит без них;
- новые клиенты на этот сервер не добавляются, а отключение и удаление клиентов применяются как обычно;
- у каждого подключения есть тестовый клиент. Его ссылку («Ссылка для теста»: `vless://`, конфигурация AmneziaWG или `tt://`) можно импортировать в клиентское приложение для проверки.

При выключении сервер сначала получает актуальные доступы клиентов и возвращается в профили только после того, как подтвердит их. Тестовый клиент при этом удаляется.

### 3.7. Служба antirkn-runner

На сервере работает служба `antirkn-runner.service`. Её устанавливает и обновляет приложение, обычно при первой установке компонента. Версия службы привязана к версии приложения: если на сервере старая версия, приложение предложит её обновить.

- Файлы службы: `/usr/local/lib/antirkn-runner/`, данные и журнал заданий: `/var/lib/antirkn-runner/`;
- служба работает от `root` под systemd: `runner.py daemon` выполняет очередь заданий, приложение обращается к ней по SSH через `runner.py rpc`;
- RPC принимает только задания заранее определённых типов, произвольные команды через него не выполняются.

### 3.8. Удаление сервера

- **Одного сервера:** «Доступ SSH» → **«Удалить сервер»**. Сначала дождитесь окончания операций и отключите SSH. Удаляются сервер и данные подключения на устройстве, настройки на самом сервере не меняются.
- **Нескольких серверов:** на вкладке «Серверы» нажмите «Редактировать список», отметьте серверы и нажмите «Удалить выбранные».
- **Недоступный сервер:** **«Забыть локально»** удаляет его с устройства без подключения. Его ресурсы и ожидающие операции убираются из профилей клиентов, но выданный ранее на сервере доступ может продолжать работать.

## 4. Протоколы

AntiRKN настраивает протоколы VLESS, AmneziaWG и TrustTunnel. Описание ниже техническое. Допустимость их использования в вашей стране оценивайте самостоятельно (см. [DISCLAIMER.md](DISCLAIMER.md)).

### 4.1. Установка и удаление протокола

- **Установка:** подключитесь к серверу и нажмите плитку протокола со статусом «Не установлен». Приложение покажет план и после подтверждения установит ПО и зависимости.
- **Удаление:** удерживайте плитку или откройте меню «Действия с протоколом» → **«Удалить протокол»**. С сервера удаляются службы и все подключения этого протокола, в том числе созданные не в AntiRKN. Для VLESS 3x-ui / Xray удаляется целиком.

Установка ПО не создаёт подключений: их добавляют на странице протокола.

### 4.2. VLESS

VLESS работает через панель **3x-ui** и ядро **Xray**.

- **Новая установка:** приложение загружает архив 3x-ui из официального релиза GitHub, проверяет его и настраивает панель. Свободный порт и случайный путь панели выбираются автоматически. Панель доступна только через SSH-туннель, логин и пароль хранятся в зашифрованном виде.
- **Существующая 3x-ui:** введите логин и пароль администратора в окне «Войти в 3x-ui». Существующие inbounds отображаются с меткой «Существующий · вне управления клиентами», их настройки и клиенты не меняются. Кнопка **«Управлять доступами клиентов»** передаёт inbound под управление AntiRKN, и после этого в нём появляются доступы ваших клиентов.

Новый inbound создаётся кнопкой **«Добавить inbound»**. Основные поля:

- «Транспорт»: **RAW/TCP · Vision** (только с REALITY) или **XHTTP** (с REALITY или TLS);
- «Адрес прослушивания», «Порт прослушивания», «Адрес подключения к inbound»;
- для REALITY — «REALITY target (хост:порт)» и «Имя сервера (SNI)». Кнопка **«Проверить Target»** проверяет с сервера TLS 1.3, HTTP/2, X25519 и сертификат цели. «Пересоздать ключи» создаёт новые ключи REALITY и Short ID;
- для TLS — пути к готовым файлам сертификата и ключа на сервере. Сертификаты для VLESS приложение не выпускает;
- для XHTTP — «Путь XHTTP», «Режим XHTTP» и «Настройки XHTTP».

Переключатель «замочек» определяет назначение inbound: **«Выдавать клиентам»** — каждый клиент получает в нём персональный доступ; **«Для внутренних нужд»** — inbound не попадает в профили клиентов. Внутренний inbound можно сделать **«Прямой выход для серверов»**: его трафик выходит прямо с сервера, а «Ссылка для серверов» используется как выходной узел для других ваших серверов (см. [4.6](#46-выход-в-интернет-через-другой-сервер)).

### 4.3. AmneziaWG

AmneziaWG — вариант WireGuard с настраиваемыми служебными полями пакетов и дополнительными пакетами перед рукопожатием. Приложение собирает AmneziaWG из исходного кода на сервере.

1. На странице AmneziaWG нажмите **«Добавить интерфейс»**.
2. Укажите «IP или домен для подключения» и «UDP-порт».
3. В «Дополнительные настройки» можно задать «Внешний UDP-порт (NAT)», «IPv4-пул клиентов (CIDR)», «IPv6-пул ULA /64 (необязательно)», MTU, PersistentKeepalive и «Начальный пакет маскировки I1». Значения по умолчанию основаны на AmneziaVPN 3.1.

План включает IP forwarding и правила для входящего UDP, пересылки и NAT этого интерфейса. Ключи и адреса клиентов создаются автоматически. Существующие установки AmneziaWG, в том числе в Docker, отображаются в «Существующие установки»; их peers и ключи при редактировании сохраняются.

### 4.4. TrustTunnel

TrustTunnel — туннель поверх TLS, для него нужен домен, указывающий на сервер.

1. На странице TrustTunnel нажмите **«Добавить endpoint»**.
2. Укажите «Порт прослушивания», «Порт подключения (внешний порт при NAT)» и «TLS-домен (SNI)».
3. «Выход в интернет»: «Напрямую» или через локальный SOCKS5 без авторизации. Дополнительно: «Разрешить выход по IPv6», «Разрешить доступ к внутренним сетям».
4. В «TLS-сертификаты» → «Добавить или выпустить сертификат» выберите источник:
   - «Готовые файлы на сервере»;
   - «Импорт файлов PEM» — полная цепочка и приватный ключ;
   - «Выпустить через ACME HTTP-01» — через Certbot (приложение может его установить). Домен должен указывать на этот сервер, TCP-порт 80 — быть свободен и доступен из интернета. Продление выполняет Certbot.

Приложение показывает срок действия сертификата и предупреждает, если до его истечения осталось меньше 21 дня. «Пересоздать пароли» меняет пароли всех клиентов endpoint.

### 4.5. Проверка подключений

На страницах протоколов у каждого подключения есть кнопка **«Проверить»**, а над списком — **«Проверить все»**. Проверка выполняется с этого устройства через встроенное ядро Mihomo и временный доступ на сервере. Результат «Соединение работает · TCP и UDP» означает, что через подключение прошли оба вида трафика. Перед проверкой отключите VPN на устройстве.

### 4.6. Выход в интернет через другой сервер

Трафик клиентов одного сервера можно направить в интернет через другой ваш сервер.

1. Откройте «О сервере» → карточку **«Выход в интернет»** → «Настроить» → **«Через другой сервер»**.
2. «Источник подключения»: «Выбрать из серверов» («Выходной сервер» и «VLESS inbound») или «VLESS-ссылка».
3. Нажмите «Применить». Для этого сервера на выходном сервере создаётся отдельный доступ.

Требования и ограничения:

- на настраиваемом сервере должна быть 3x-ui;
- TCP и UDP направляются через VLESS, прежние правила маршрутизации Xray имеют приоритет;
- если выходной сервер недоступен, автоматического переключения на прямой выход нет;
- AmneziaWG в отдельной Docker-сети пока не поддерживается.

## 5. Клиенты

Клиент — это человек или устройство, которому вы выдаёте доступ. Клиент создаётся один раз, и приложение само подготовит ему персональные доступы ко всем управляемым подключениям на всех серверах: VLESS inbounds в режиме «Выдавать клиентам», интерфейсам AmneziaWG и endpoint TrustTunnel.

### 5.1. Создание клиента

1. На вкладке «Клиенты» нажмите **«Добавить клиента»** (или «+» в заголовке).
2. Введите «Отображаемое имя».
3. Оставьте включённым «Включён».
4. При необходимости включите «Индивидуальный базовый конфиг» (см. [5.2](#52-индивидуальный-базовый-конфиг)).
5. Если публикация в Google Drive настроена, можно указать существующий файл профиля: поле «Ссылка Google Drive или ID файла» или кнопка «Выбрать в Google Drive».
6. Нажмите «Сохранить».

Список можно сортировать по имени или дате создания. Отключённые клиенты собраны в группе «Отключенные клиенты».

### 5.2. Индивидуальный базовый конфиг

По умолчанию профиль клиента собирается по общему базовому конфигу из настроек. Переключатель **«Индивидуальный базовый конфиг»** в окне клиента позволяет выбрать для него отдельный YAML-файл Mihomo, например с другими группами, правилами или DNS.

### 5.3. Отправка изменений на серверы

После сохранения клиента приложение в фоне отправляет изменения на все серверы. Если сервер недоступен, изменение ждёт его и отправляется при следующем подключении. Пока сервер не подтвердил доступ, в окне профиля клиента есть кнопка **«Применить план на всех указанных серверах»**.

Если другое ваше устройство уже применяет изменения, приложение покажет это и будет обновлять статус. Кнопка «Проверить и продолжить на этом устройстве» позволяет продолжить операцию здесь.

### 5.4. Отключение и удаление

- **Отключение:** переключатель на карточке клиента. Доступы на серверах отключаются, клиент остаётся в списке.
- **Удаление:** нажмите «Редактировать список», отметьте клиентов и нажмите «Удалить выбранные». В диалоге удаления можно отметить «Также переместить файл конфигурации в корзину Google Drive». Доступы на недоступных серверах отзываются после их подключения. Имя можно использовать снова.
- **«Удалить принудительно»:** пока отзыв доступа ждёт недоступные серверы, эта кнопка есть в уведомлении об изменениях на серверах. Клиент сразу исчезает из приложения. На недоступных серверах его доступ может ещё работать, пока приложение не завершит отзыв при следующем подключении.

### 5.5. Трафик клиентов

В окне профиля клиента показан **«Трафик»**: «Скачано» и «Отправлено» за «Всё время», график «По месяцам» и разбивка «По серверам». На серверах считаются только объёмы, соединения и сайты не записываются. Если на сервере старая версия runner, приложение попросит её обновить.

## 6. Профили и раздача

### 6.1. Базовый конфиг и профиль Mihomo

Профиль клиента — YAML для Mihomo. Он собирается из базового конфига, то есть шаблона с группами прокси, правилами и DNS, и узлов клиента на всех серверах.

1. Откройте **Настройки → «Клиентские профили»** → «Базовый конфиг» → «Выбрать файл» и выберите `.yml` или `.yaml`. Пример шаблона — [base.yml](base.yml) в репозитории.
2. Приложение сохраняет свою копию файла, исходный файл не меняется. Шаблон проверяется встроенным Mihomo; при ошибке остаётся прежний базовый конфиг.
3. Позже файл можно заменить кнопкой «Заменить».

Без базового конфига профили не собираются. Узлы серверов в сервисном режиме в профили не попадают.

Профиль открывается кнопкой **«QR подключения»** на карточке клиента. Там же:

- «Просмотр YAML» и **«Сохранить YAML»** — сохранить профиль в файл;
- «Подробности профиля»;
- «Перепроверить серверы и перегенерировать профиль» (кнопка обновления).

Если текущий профиль ещё не готов, сохраняется последняя корректная версия.

### 6.2. Публикация в Google Drive

Публикация сохраняет YAML клиентов в папку вашего Google Drive и при изменениях обновляет тот же файл, поэтому ссылка остаётся прежней.

1. Войдите в Google (см. [7.1](#71-синхронизация-через-google-drive)).
2. **Настройки → «Клиентские профили» → «Публикация в Google Drive»**: «Разрешить публикацию в Drive», затем «Настроить публикацию».
3. «Папка»: «Создать папку AntiRKN profiles» или «Выбрать доступную приложению папку».
4. «Доступ к профилям»:
   - **«Приватный файл»** — файл хранится в Drive, но клиентское приложение не скачает его по ссылке без входа в Google;
   - **«Доступ по ссылке»** — профиль может скачать любой, у кого есть ссылка. Файл содержит доступы клиента и не шифруется.
5. «Автоматическая публикация» включает выгрузку после каждого изменения.

Папку настраивают на одном устройстве, остальные получают настройку через синхронизацию. Кнопка **«Выгрузить проверенные профили»** на вкладке «Клиенты» выгружает профили вручную. Удержание кнопки запускает полную сверку с серверами перед выгрузкой.

Если файл на Drive изменили не из AntiRKN, публикация останавливается с сообщением «Версия на Drive изменилась». Кнопка **«Перезаписать принудительно»** записывает в файл текущий профиль.

### 6.3. QR-код и ссылка

При публикации с «Доступ по ссылке» в окне «QR подключения» показан QR-код с прямой ссылкой на YAML:

1. отсканируйте его в клиентском приложении на базе Mihomo или нажмите на QR, чтобы скопировать ссылку;
2. клиентское приложение обновляет профиль по своему расписанию (часто раз в 24 часа), если оно запущено и есть сеть.

Без публикации профиль передаётся файлом через «Сохранить YAML».

## 7. Резервное копирование и синхронизация

### 7.1. Синхронизация через Google Drive

Синхронизация переносит данные приложения между вашими устройствами через один Google-аккаунт.

1. **Настройки → «Мои данные» → карточка «Синхронизация»**.
2. Нажмите **«Войти в Google»**. На Windows и Linux вход открывается в системном браузере; при первой настройке приложение попросит JSON-файл клиента Desktop OAuth из вашего Google Cloud проекта.
3. Включите **«Автосинхронизация»**. Изменения отправляются примерно через 30 секунд после правки и при уходе приложения в фон, новая версия загружается при возвращении в приложение. Кнопка «Синхронизировать» запускает обмен вручную.
4. На другом устройстве войдите в тот же Google-аккаунт.

Снимок данных хранится в скрытой папке приложения (`appDataFolder`) вашего Google Drive в зашифрованном виде. Ключ снимка хранится там же, поэтому доступ к данным определяется доступом к Google-аккаунту. OAuth-токены остаются на устройстве. Работать на устройствах лучше по очереди.

После загрузки данных с другого устройства сведения о серверах перечитываются в фоне. Пока этого не произошло, показываются сохранённые данные с датой.

### 7.2. Выбор версии данных

Если на этом устройстве есть неотправленные изменения, а в Google Drive лежит другая версия, приложение их не объединяет. Появится статус «Нужно выбрать версию данных» и кнопка **«Выбрать версию»**:

- **«Оставить данные этого устройства»** — версия в Google Drive будет заменена;
- **«Взять из облака»** — неотправленные изменения этого устройства будут заменены.

Пока выбор не сделан, действия на серверах заблокированы. Если данные в Google Drive сохранены более новой версией AntiRKN, обновите приложение.

### 7.3. Резервные копии

**Настройки → «Резервные копии»**:

1. **«Резервная копия»** сохраняет серверы, клиентов, ключи, шаблоны и историю изменений в файл `.antirkn`.
2. Задайте отдельный пароль длиной от 12 символов. Файл шифруется AES-256-GCM, пароль приложение не сохраняет. Без пароля восстановить копию нельзя.
3. **«Восстановить»** → «Выбрать файл» → введите пароль. Приложение покажет дату создания, число серверов и клиентов.
4. **«Заменить и восстановить»** заменяет текущие серверы, клиентов и шаблоны содержимым копии. SSH-соединения закроются. Если текущие данные нужны, сначала сохраните их отдельной копией.

Размер резервной копии ограничен 64 МиБ. Если в копии есть незавершённые операции на серверах, после восстановления приложение попросит проверить состояние сервера.
