# Google Drive: настройка проекта AntiRKN

Состояние на 2026-09-16: вход в один Google-аккаунт автоматически подключает устройства и объединяет их данные без ручного backup/restore. Ключи передаются через закрытую appDataFolder. Данные старой версии становятся доступны после первого открытия обновлённой установки, где они уже есть. Настройка проекта завершена; JSON клиента остаётся вне Git и сборок. Реальный обмен новой версии на физических устройствах ещё не проверен. Ниже — инструкция для повторного развёртывания.

## 1. Создать проект

1. Откройте [создание проекта Google Cloud](https://console.cloud.google.com/projectcreate).
2. Войдите в Google-аккаунт, который будете использовать для синхронизации на компьютере и телефоне.
3. **Project name / Название проекта:** `AntiRKN`.
4. **Project ID:** оставьте предложенный уникальный ID. Запишите его: это идентификатор проекта, не пароль.
5. **Organization / Организация:** для личного аккаунта оставьте `No organization`, если такой выбор доступен. Рабочая организация может ограничивать создание проектов.
6. Нажмите **Create / Создать**, дождитесь завершения. В переключателе проекта сверху выберите именно `AntiRKN`.

Основание: [создание проекта](https://developers.google.com/workspace/guides/create-project).

## 2. Включить Drive API

1. Откройте [Google Drive API](https://console.cloud.google.com/apis/library/drive.googleapis.com).
2. Проверьте выбранный проект `AntiRKN` вверху.
3. Нажмите **Enable / Включить**. Если видите **Manage / Управление**, API уже включён.

Основание: [включение API](https://developers.google.com/identity/protocols/oauth2/native-app#enable-apis).

## 3. Настроить окно входа Google

1. Откройте [Google Auth Platform → Branding](https://console.cloud.google.com/auth/branding).
2. Если предложено, нажмите **Get started / Начать**.
3. **App name:** `AntiRKN`. **User support email:** ваш адрес.
4. **Audience:** `External` для личного Google-аккаунта.
5. **Contact information:** ваш адрес. Прочитайте предложенные условия и подтвердите их, если согласны; завершите мастер.
6. Откройте **Audience / Аудитория**. Оставьте статус **Testing / Тестирование**. В **Test users → Add users** добавьте адрес Google-аккаунта, которым будете входить. Сохраните.
7. Откройте **Data Access → Add or remove scopes**. Добавьте `https://www.googleapis.com/auth/drive.appdata`, затем **Update → Save**. В некоторых версиях консоли scope добавляется через поле ручного ввода внизу списка.

Основание: [экран согласия и scopes](https://developers.google.com/workspace/guides/configure-oauth-consent). `drive.appdata` предназначен для закрытых служебных файлов; публикация YAML потребует отдельной настройки `drive.file` в своей стадии: [appDataFolder](https://developers.google.com/workspace/drive/api/guides/appdata).

## 4. Создать клиент для Linux/Windows

1. Откройте [Google Auth Platform → Clients](https://console.cloud.google.com/auth/clients).
2. Нажмите **Create client**.
3. **Application type:** `Desktop app`.
4. **Name:** `AntiRKN Desktop`.
5. Нажмите **Create**. Скачайте JSON через **Download JSON**; если окно закрыто, откройте созданный клиент в списке.
6. Сохраните файл в обычную папку загрузок вне репозитория, например `~/Downloads/antirkn-desktop-oauth.json`.
7. Сообщите агенту **только полный путь к этому файлу** и Project ID. Содержимое JSON, токены, пароль и коды входа в чат вставлять не нужно.

Для Desktop app не нужно заводить сайт или заполнять redirect URI веб-клиента. Системный браузер вернёт результат в локальный loopback listener при проверке входа. Основание: [Desktop credentials](https://developers.google.com/workspace/guides/create-credentials#desktop-app), [native OAuth](https://developers.google.com/identity/protocols/oauth2/native-app).

## 5. Создать Android-клиент в том же проекте

1. В **Clients → Create client** выберите **Android**.
2. **Name:** `AntiRKN Android Debug`.
3. **Package name:** `org.antirkn.antirkn_manager`.
4. **SHA-1 certificate fingerprint** текущей debug-сборки на этом компьютере:

   ```text
   AF:BC:86:8C:12:24:C6:42:14:76:50:06:B7:39:79:59:64:47:74:AA
   ```

5. Создайте клиент. Сохраните его Client ID для последующей настройки Android-входа.

Package name прочитан из `apps/manager/android/app/build.gradle.kts`; отпечаток получен из локального debug-сертификата, приватный ключ не экспортировался. После перехода на релизную подпись потребуется клиент для её сертификата. Настройка клиента в консоли сама по себе ещё не реализует вход в Android-приложении. Основание: [Android credentials](https://developers.google.com/workspace/guides/create-credentials#android).

## Повторная проверка на Linux

Из корня репозитория:

```bash
python3 tool/google_drive_setup.py \
  --client ~/.config/antirkn/google/desktop-client.json \
  --login \
  --evidence docs/evidence/drive-live.json
```

Откроется системный браузер. Выберите созданный тестовый аккаунт, прочитайте запрошенный доступ и подтвердите его. После возврата в локальную вкладку вернитесь в терминал: там появятся результаты без токенов. Проверка создаёт один синтетический зашифрованный файл в служебной области и удаляет только свой выделенный ID. Access token остаётся в памяти; очередной запуск снова требует входа. Это отдельный одноразовый CLI probe. В GUI настольного приложения сессия сохраняется зашифрованно, а access token обновляется автоматически.

Чтобы импортировать заново скачанный Desktop JSON, передайте его путь через `--client`. Для сохранения Android ID дополнительно укажите `--android-client-id <Client ID>`. Это публичный ID; он должен иметь тот же номер проекта, что Desktop-клиент. При повторном импорте того же Desktop-клиента уже сохранённый Android ID сохраняется.

Если Google показывает `access_denied`, проверьте аккаунт в **Audience → Test users** и что он выбран в браузере. При `redirect_uri_mismatch` проверьте, что скачан именно **Desktop app**, а не Web application. При `accessNotConfigured`/отключённом API вернитесь к шагу 2. Текст ошибки можно сообщить без паролей, кодов входа и токенов. Параметры конкретных клиентов и их JSON в репозиторий не добавляйте.

## Собрать Android с кнопкой входа

С 2026-09-16 Android-сборка любого режима останавливается перед компиляцией Flutter, если отсутствует или некорректен `ANTIRKN_GOOGLE_PROJECT_ID`. Без него сохранённый аккаунт не восстанавливается, а вход заканчивается ошибкой конфигурации. Возврат правильного ID восстанавливает прежнюю локальную привязку; очистка данных приложения не требуется.

Для текущей конфигурации владельца, включая Picker, из `apps/manager`:

```bash
flutter build apk --release --target-platform android-arm64 --no-pub \
  --dart-define-from-file="$HOME/.config/antirkn/google/binding-build-defines.json"
```

Для debug используйте `--debug` с тем же внешним файлом. JSON содержит только публичные параметры сборки; Desktop client secret и OAuth-токены туда не добавлять. Проверка формата ID не заменяет проверку Android package/SHA-1 в Google Cloud.

После импорта клиентов запустите из корня проекта:

```bash
python3 tool/google_drive_setup.py \
  --client ~/.config/antirkn/google/desktop-client.json \
  --build-android
```

Команда передаст в APK публичный project ID; Desktop client secret и JSON в APK не попадут. Установите полученный `apps/manager/build/app/outputs/flutter-apk/app-debug.apk` поверх прежней версии с сохранением данных.

В приложении откройте **Настройки → Синхронизация → Google Drive → Войти в Google**, выберите свой тестовый аккаунт и разрешите доступ к Drive. После успешной проверки появятся имя/email и кнопки **Сменить аккаунт / Выйти**. Закрытие окна Google не меняет прежний аккаунт. Выход отключает эту установку и не удаляет файлы Drive. Google Play services должны быть доступны на телефоне.

Если показана ошибка настройки, проверьте: собран APK этой командой, в Google Cloud есть Android-клиент с указанными package/SHA-1, использован сертификат текущей сборки, выбранный аккаунт добавлен в Test users. После смены подписи потребуется зарегистрировать её SHA-1. Ручная проверка выбранного аккаунта/согласия на телефоне требует участия владельца; её результат фиксируется отдельно.


## Автосинхронизация и подключение второго устройства

1. Откройте **Настройки → Синхронизация → Google Drive**. После входа переключатель **Автосинхронизация** включён по умолчанию; при желании его можно выключить. Выбор сохраняется на устройстве.
2. Сохраняйте данные как обычно: отправка начнётся примерно через секунду. Приложение также проверяет Drive при открытии/возврате и через 30 секунд, пока находится на экране. Для немедленного запроса есть **Синхронизировать сейчас**.
3. В карточке видны ход обмена и время последнего завершённого обмена. При отсутствии сети данные остаются в локальной очереди, попытки повторяются автоматически. Если Google отозвал доступ, снова нажмите вход/смену аккаунта и подтвердите доступ.
4. Если данные получены, но ожидают применения, сохраните правки, закройте редактор сервера и перейдите в настройки или список серверов. Дождитесь завершения текущих операций. При конфликте выберите нужную версию в разделе конфликтов ниже.
5. На втором устройстве войдите в тот же Google-аккаунт. Серверы, клиенты и секреты появятся автоматически; существующие данные объединяются. Резервную копию для этого создавать и переносить не нужно.
6. Если данные созданы старой версией, обновите и откройте приложение на устройстве, где они уже есть. Оно автоматически передаст ключ через закрытую область Drive. После этого второе устройство перечитает прежние данные.

Доступ к данным определяется входом в Google. Ключи хранятся в закрытой appDataFolder; этот режим не обещает E2EE-защиту от самого провайдера. Локальные записи зашифрованы, OAuth-токены остаются на устройстве, публичные профили отделены от служебных данных. [Политика конфиденциальности](../PRIVACY.md).

При полностью закрытом приложении обмен продолжится при следующем открытии. Настольное видимое окно может продолжать обмен без фокуса; Android обменивается, пока приложение на экране. Пароль копии, JSON клиента и токены не отправляйте в чат.


## Войти на Linux / Windows

1. Откройте **Настройки → Синхронизация → Google Drive → Войти в Google**.
2. На Linux используется ранее настроенный `~/.config/antirkn/google/desktop-client.json` (или каталог из `XDG_CONFIG_HOME`); на Windows — `%APPDATA%/antirkn/google/desktop-client.json`. При отсутствии файла приложение предложит выбрать скачанный **Desktop app JSON** через системный диалог. Android и Desktop OAuth-клиенты должны принадлежать одному Google-проекту.
3. Завершите вход в системном браузере и вернитесь в AntiRKN. Ожидание можно отменить; прежний аккаунт сохранится.
4. Аккаунт и refresh token сохраняются зашифрованно только на этом устройстве; после перезапуска повторный вход обычно не нужен. При отзыве доступа интерфейс попросит войти снова. **Выйти** отключает только локальную сессию.
5. На всех устройствах используйте обновлённый AntiRKN и один Google-аккаунт. Перенос ключа и объединение данных выполняются автоматически по шагам выше.

В предыдущей версии Linux-вход и обмен после ручного переноса копии подтверждены владельцем; новый автоматический обмен проверен на изолированных базах и HTTP-стенде, реальная пара устройств пока не принята. Windows-адаптер включён, но Windows build/runtime пока не проверен. [Решения и границы P1-06b](adr/0019-desktop-google-account.md).

## Существующие ссылки клиента: Google Picker

В том же Cloud-проекте включите **Google Picker API** и **Google Drive API**. В **APIs & Services → Credentials → Create credentials → API key** создайте публичный ключ и ограничьте его этими двумя API. Скопируйте числовой **Project number** из **IAM & Admin → Settings**. Для текущего loopback Picker OAuth-клиенты пересоздавать не требуется: используется существующий access token.

В AntiRKN: **Настройки → Drive → Настройка Google Picker** — API key и Project number. Настройки сохраняются в зашифрованном workspace. Сборка может задавать начальные значения через `ANTIRKN_GOOGLE_PICKER_API_KEY` и `ANTIRKN_GOOGLE_PICKER_APP_ID`; конфигурацию владельца хранить вне Git. Ключ публичный, OAuth Desktop secret в эти поля и сборки не передавать. В сборках стадии от 2026-09-15 начальные значения владельца уже заданы.

1. Настройте и включите публикацию в Drive; для подписок выберите доступ по ссылке.
2. **Клиенты → открыть клиента → Изменить файл / ссылку**. Несохранённые изменения клиента сначала сохраните.
3. Вставьте старую ссылку и нажмите **Проверить файл**. Если AntiRKN ещё не имеет доступа, нажмите **Выбрать в Google Drive**, выберите этот файл в браузере и вернитесь в приложение.
4. Проверьте название/ID, старый текст и профиль для замены. **Заменить и привязать** сохраняет согласие и запускает публикацию. На телефоне браузер может оставаться открыт после выбора — вернитесь в AntiRKN.
5. После проверки загрузки/скачивания QR использует новый файл. Его прежний ID и ссылки сохраняются; старый автоматически созданный файл не удаляется и больше не обновляется.

Утерянный ответ/сеть восстанавливаются очередью. Если файл изменён после предпросмотра — повторно проверьте и подтвердите; можно выбрать другой файл. Приложение не пишет в файлы другого клиента. Папки и Google Docs не подходят; нужен редактируемый текстовый файл UTF-8. Все устройства workspace должны быть обновлены до версии с поддержкой реестра v2.

Публичный ключ и номер проекта должны совпадать с проектом OAuth-клиентов. При ограничениях ключа по Websites учитывайте loopback origin и iframe `docs.google.com` согласно [инструкции Google](https://developers.google.com/workspace/drive/picker/guides/web-picker-sample). Один только доступ к файлу в браузере или наличие старой ссылки не выдаёт `drive.file` разрешение приложению.
