# Подтверждённые требования и рабочие решения

Источник: `AGENT_TASK.md`, `TECHNICAL_PLAN.md` 0.8 и прямые уточнения владельца 12–13 сентября 2026. Все исходные Markdown прочитаны до реализации. Наличие заготовки или прошедшего парсера не означает завершения P0–P7.

## Подтверждено владельцем

- Уточнение 2026-09-13: сейчас один VPS с несколькими назначенными IP; несколько серверов, RU/EU-сценарии и double hop — будущее расширение. Согласована итерация P0: модель/парсер каталога, правила выбора IP, общий компонент и локальный прототип, проверки и Linux/Android сборки без телефона. После отчёта выключить ПК. Это не отменяет RU/EN-локализацию и не разрешает менять исходный `base.yml`.
- Windows/Linux/Android, полноценное администрирование на Android; приложение не является VPN-клиентом.
- Material 3 / Material You, общие компоненты, motion/reduced motion, чистая архитектура, DRY/SOLID.
- Ubuntu без ограничения версии — прямое уточнение владельца 2026-09-13. VERSION_ID используется для отображения, а не допуска подключения. x86_64: в §18 ТЗ владелец отметил, что этой архитектуры достаточно. arm64 сервера не добавляем.
- Только заданные VLESS RAW/REALITY/Vision и VLESS XHTTP REALITY/TLS, TrustTunnel, AWG; экспорт только Mihomo.
- SSH с закреплением host key и раздельными секретами, безопасная смена доступа, продолжающийся на VPS runner.
- Уточнение владельца: постоянное защищённое хранилище реализуется в одной стадии с SSH. Приватный ключ импортируется системным диалогом без привязки к внешнему пути; подключение и секреты восстанавливаются после перезапуска. На Linux доступно использование локального SSH-agent; `.pub` — публичная часть, для файлового входа нужен приватный ключ.
- Уточнение владельца: локальный Git обязателен; после завершения каждой согласованной стадии выполнить проверки, обновить отчёт и создать локальный коммит. Правило закреплено в `AGENTS.md` и `AGENT_TASK.md`.
- Подключение выполняет только инвентаризацию; установка предлагается с выбором компонентов и возможностью «Не сейчас». Поздняя установка из карточки сервера повторяет обнаружение и подтверждение плана. Не запускаем bootstrap, пакеты, службы или firewall по одному факту подключения (FR-PROV-02, AC-38).
- Каталог реально назначенных адресов через `ip -j`, единый локальный scanner на устройстве, без API провайдера и массового сканирования VPS.
- Один основной YAML пользователя, стабильные ID/credentials/fileId, сохранение исходного `base.yml` и политики групп.
- Базовый YAML выбирается системным файловым диалогом и читается в память приложения. Используется независимая копия содержимого; исходный файл не изменяется, отмена/ошибка сохраняет текущий шаблон. Автоматической загрузки встроенного base.yml нет (FR-PROFILE-01, AC-39).
- Автоматическая E2EE-синхронизация сущностей/секретов через Google Drive appDataFolder; выдаваемые YAML отдельно. OAuth-токены остаются локальными.
- RU/EN и автовыбор по системе, ручной выбор языка. В ТЗ добавлены FR-UI-04 и AC-37.

## Рабочие инженерные решения этой итерации

- Flutter/Dart workspace: GUI, design_system, domain, profile_compiler, storage. Не создаём фиктивные интеграции на месте будущих модулей.
- Для остальных языков системы fallback — английский. Язык сохраняется отдельно на каждом устройстве; не изменяет YAML и имена ресурсов.
- ARB + `flutter gen-l10n`; enum и контракт хранения языка в domain, платформенное хранение несекретного выбора в storage.
- Первое сквозное локальное упражнение P0: шаблон → строгий разбор → состав групп → диагностический результат; компиляция публичных fixtures → настоящий `mihomo -t`.
- GUI явно помечен «Прототип P0». Тестовые имена узлов не являются созданными серверными доступами. Редактор шаблона пока хранится в памяти.
