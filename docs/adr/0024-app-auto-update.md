# ADR 0024: подписанное обновление приложения из GitHub Releases

Принято 2026-11-27 по решению владельца (стадия release CI/CD + автообновление).

Источник — GitHub Releases публичного репозитория `CyberCat2033/AntiRKN`. Клиент читает `releases/latest/download/app-update-<channel>.json`; сеть только HTTPS к путям `/CyberCat2033/AntiRKN/releases/` на github.com и переадресация на CDN выпусков (`release-assets.githubusercontent.com`, прежний `objects.githubusercontent.com`; проверено 2026-11-27). Другие хосты, порты, userinfo и более пяти переадресаций отклоняются.

Манифест — конверт `{"format","signatures","payload"}`; payload — base64url байтов JSON. Подпись Ed25519 над `antirkn-app-update-v1` + 0x00 + байты payload проверяется **до** разбора. Допускается несколько подписей (ротация): ключ `k1` в GitHub Environment `release`, резервный `k2` у владельца офлайн. Публичные ключи — в коде (`packages/app_update/lib/src/trusted_keys.dart`); пустой список означает «обновления недоступны в этой сборке». Срока действия нет; от отката защищают монотонный `build` и запоминаемый максимальный увиденный `build`. Он хранится в настройках workspace, но при каждой проверке берётся не ниже build установленной версии, поэтому восстановленный старый бэкап не открывает путь к понижению версии.

Payload описан один раз в `schemas/app-update-v1.json`; Dart-модель генерирует `tool/generate_app_update.py` (`--check` в `tool/verify.sh`). Правила, которые схема не выражает (tag = v+version, build = X·10000+Y·100+Z, URL = префикс+tag+имя, Android versionCode = build·10+abiId, только Android-поля у APK, порядок changelog), проверяет домен. В payload входит changelog (EN/RU, до 20 версий, 64 КиБ на язык) из `CHANGELOG.md`/`CHANGELOG.ru.md` в формате Keep a Changelog: текст аутентифицирован подписью и не требует второго запроса. Тот же парсер строит тело GitHub Release (`release-notes`).

Политика (домен, чистый Dart): тот же appId и канал; build строго больше установленного и не меньше максимального увиденного; артефакт по виду установки. Android сохраняет установленный вариант ABI (versionCode % 10), universal — только если варианта нет. Десктоп определяет вид по файлу `install-kind` рядом с исполняемым файлом (AppImage дополнительно требует `$APPIMAGE`); без метки — только ссылка на страницу выпуска.

Загрузка идёт во временный каталог (`<temp>/antirkn-update`), никогда не в каталог данных; потоковый SHA-256, лимит размера по манифесту, докачка через Range, переименование `.part` только после совпадения размера и хеша. Установка:
- Android — PackageInstaller.Session; перед сессией сверяются packageName, точный versionCode (> установленного) и набор сертификатов подписи с установленным и с `certSha256` манифеста; `STATUS_PENDING_USER_ACTION` открывает системное подтверждение; без разрешения открываются настройки «Установка из этого источника».
- Linux AppImage — `$APPIMAGE` должен быть обычным файлом (не ссылкой) пользователя (не root) в записываемом каталоге; копия `.part` с проверкой хеша, chmod 755, fsync, атомарная замена; прежний файл — `.old` до подтверждённого запуска.
- Linux tar.gz — распаковка в соседний `.new` без ссылок, устройств, `..` и абсолютных путей, один верхний каталог `AntiRKN-vX.Y.Z-linux-x64/`; журнал шагов, переименование каталога в `.old` до подтверждённого запуска; иначе только уведомление.
- Windows installer — Inno Setup `/VERYSILENT /SUPPRESSMSGBOXES /NORESTART /CLOSEAPPLICATIONS /relaunch=1`, приложение завершается.
- Windows portable — только загрузка, проверка и показ файла (замена файлов — следующая стадия).

Перед заменой файлов на десктопе закрывается шлюз воркера Mihomo (`MihomoWorkerGate`) и ожидается завершение активных запусков; при таймауте установка не начинается. Перед запуском установщика или нового процесса и выходом приложение выполняет своё штатное закрытие (сброс синхронизации, закрытие сеанса и базы workspace) — не дольше 10 с; медленное или неудачное закрытие обновление не блокирует. Успех подтверждает следующий запуск по фактическому build (тогда удаляется `.old`). В журнал и stderr попадают только коды ошибок. Переключатели «Проверять новые версии» и «Предлагать обновления» теперь относятся к приложению (их прежние значения переносятся один раз); проверки компонентов серверов включены всегда.

Проверено unit- и widget-тестами с фейками и временными каталогами. Не проверены: реальная установка на Android-устройстве, Windows, реальный AppImage/tar.gz-релиз и сеть GitHub.
