## 1. Принципы

- Лаконичность: одно основное действие на экране, минимум постоянных кнопок и пояснений.
- Общий Material Design 3 / Material You на Android, Linux и Windows: семантические цвета, типографика, размеры, компоненты и анимации.
- В основном представлении — объект, актуальное состояние и следующий нужный шаг. Технические подробности раскрываются по запросу.
- Ошибки, конфликты, частичное выполнение и ожидающий отзыв доступа остаются заметными.
- Рутинные операции автоматизированы; установка ПО и применение серверных изменений — через краткий план с одним подтверждением.
- Сохранённая инвентаризация не доказывает доступность сервера, SSH не доказывает работу VPN, счётчик трафика не является суточной статистикой. Новые метрики и пинги без реального источника данных не добавлять.

## 2. Навигация

Три постоянных раздела: **Серверы · Клиенты · Настройки**. Начальный экран — серверы. Загрузка зависимостей не меняет порядок или число разделов. Отдельный дашборд, обзор P0 и вкладка Templates отсутствуют.

| Доступная ширина, логические пиксели | Компоновка |
| --- | --- |
| Менее 600 | NavigationBar, переход список → детали, отступы 16 |
| 600–839 | NavigationRail, одна основная панель, отступы 24 |
| 840–1199 | Rail и список/детали рядом при достаточном месте |
| От 1200 | Расширенная навигация, ограниченная ширина содержимого |

Учитывать высоту окна, клавиатуру, масштаб текста и способ ввода. При resize сохранять выбранный объект, черновик, прокрутку и фокус.

В шапке — название раздела/объекта и один компактный индикатор синхронизации с переходом к состоянию Drive. Постоянный аватар аккаунта не нужен. Активная задача/ошибка отображается компактной строкой с переходом к подробностям. Очереди не дублируются на каждом экране; отмена/восстановление доступны по возможностям реальной операции.

## 3. Серверы

### Каталог

- Строка или тональная карточка: имя, адрес, краткое состояние.
- Нажатие на всю строку открывает сервер; отдельной кнопки «Открыть» нет.
- Одно действие создания — «+» справа сверху, с tooltip и semantics «Добавить сервер».
- Режим редактирования каталога с карандашом и баннером удаления не вводится.
- Различать подключение, отсутствие свежих сведений и ошибку; не показывать «Онлайн» по наличию сохранённого профиля.

### Детали

Обычный `TabBar`: **Протоколы · Обслуживание · Подключение**. По дополнению владельца со скриншотом кнопка подключения/отключения находится справа в шапке рядом с ⋮; ссылка Connection под вкладками и дубль кнопки в SSH-панели убраны.

| Вкладка | Основное содержимое | По раскрытию/в меню |
| --- | --- | --- |
| Протоколы | VLESS, AWG, TrustTunnel; краткие параметры и состояние; одно действие добавления | Редактор, расширенные параметры, peers, сертификаты |
| Обслуживание | Установленные компоненты, версии, найденные обновления, текущая операция | Ручная проверка релизов, журналы, пути, hashes |
| Подключение | SSH, публичные адреса, параметры доступа | Jump-хост, дополнительные сведения, сокеты ОС |

APT запускается вручную. Новый release не означает готовности установки через приложение: показывать только реализованные действия конкретного компонента.

Удаление сервера — в одном месте: **⋮ в деталях → Удалить сервер**. Подтверждение объясняет удаление записи управления, сохранённых секретов и синхронизацию удаления; VPS и установленное ПО сохраняются. До удаления проверяются активные операции и зависимости, включая jump-хосты. Отказ не должен выглядеть успехом. Пример `deleteServer()` из старого аудита не является готовой реализацией.

## 4. Клиенты

Каталог: одно действие добавления в шапке, согласованное с каталогом серверов. Строка показывает имя, краткое состояние доступа/публикации и одну кнопку выдачи профиля. Нажатие на строку открывает настройки клиента. Переключатели блокировки на каждой строке не нужны.

Редактор: login, отображаемое имя, состояние доступа, строка «Файл конфигурации». После сохранения автоматически готовится краткий план. Постоянные кнопки «Подготовить», «Пересобрать профили» и «Обновить список» убираются. Выдача/отзыв управляемых доступов — через план, с явным ожиданием недоступных серверов.

### Удаление клиента

Путь: **детали клиента → ⋮ → Удалить клиента**.

1. Один диалог подтверждает удаление клиента и отзыв всех его управляемых доступов.
2. Дополнительный флажок **«Также удалить файл конфигурации из Google Drive»**, по умолчанию выключен. Показывать конкретный привязанный файл; сменившееся назначение нельзя удалить по старому подтверждению.
3. До внешних эффектов сохраняется намерение удаления; новые публикации и выдачи доступа прекращаются.
4. Отзыв выполняется на всех затронутых серверах. При offline клиент убирается из обычного активного списка, но операция **«Ожидает отзыва доступа»** остаётся видимой и восстанавливается после перезапуска.
5. Успех — после проверки отзыва. Удаление YAML само по себе не отзывает скачанные credentials. Ошибка очистки Drive показывается отдельно от успешно выполненного отзыва.
6. Удаление синхронизируется через tombstones; старая offline-копия не воскрешает клиента. До завершения сохраняется минимум данных для отзыва и восстановления.

**Имя и login можно использовать повторно.** Новый USER получает новый ID и новые ключи; запрет старой записи не является запретом имени.

Имена прокси: `ClientName_NodeName`, где ClientName — отображаемое имя клиента, NodeName — название inbound VLESS либо редактируемая подпись узла AWG/TrustTunnel. При совпадениях допустим устойчивый числовой суффикс.

Флажок относится только к выбранному файлу клиента; общая папка и произвольные старые файлы не удаляются.

## 5. Выдача профиля и QR

Одно окно: sheet на компактном экране, ограниченный диалог на широком. Заголовок — имя клиента.

- **QR кодирует проверенную прямую ссылку на скачивание YAML**, а не страницу просмотра/входа или сырой YAML.
- **Нажатие на QR копирует ровно эту ссылку в буфер обмена.** Под QR: «Нажмите, чтобы скопировать ссылку».
- После успешной записи — snackbar **«Ссылка скопирована»**. При отказе буфера показать ошибку; повтор выполняется нажатием на тот же QR. Выделяемый текст ссылки допустим как резервный способ при ошибке.
- **Отдельной кнопки получения/копирования ссылки нет**, в том числе в строке клиента. Кнопка выдачи открывает это окно.
- Сохранение YAML — отдельное действие. Содержимое доступно под свёрнутым «Просмотр YAML».
- QR — доступная кнопка с focus, Enter/Space, tooltip и semantics «Скопировать прямую ссылку на профиль …».

| Состояние | Окно выдачи |
| --- | --- |
| Актуальная публичная публикация, ссылка проверена без Google-сессии | Доступен QR |
| Первая публикация ожидается | Краткий статус, QR ещё отсутствует |
| Есть предыдущая проверенная публикация | Прежний QR допустим с явным статусом «Обновление ожидается»; старую ревизию не называть актуальной |
| Приватный файл или доступ к ссылке утрачен | QR отсутствует; локальное сохранение валидного YAML доступно |
| Ошибка/конфликт | Причина и действие восстановления; случайная новая ссылка не создаётся |

## 6. Настройки

Четыре короткие группы; строка показывает текущее значение, подробности открываются нажатием:

1. **Google Drive**: аккаунт, обмен, публикация, папка конфигураций и выбранная политика доступа. Ошибки/конфликты показываются при наличии. Ручной запуск — в подробностях, повтор — при необходимости.
2. **Резервные копии**: экспорт и восстановление с существующим предпросмотром замены.
3. **Базовый профиль**: имя YAML и выбор другого файла. Исходник владельца не перезаписывается. Группы/диагностика раскрываются; предупреждения совместимости не блокируют выдачу.
4. **Оформление**: системная/светлая/тёмная тема, системный/русский/English язык, системные/уменьшенные/отключённые анимации. Существующие настройки отключения проверки/предложения релизов также сохранить в подробностях настроек приложения.

**Базовая папка** хранит клиентские конфиги в Drive; **базовый профиль** — YAML для их сборки. Это разные настройки с разными названиями.

### Смена базовой папки

Путь: **Настройки → Google Drive → Папка конфигураций → Изменить**.

1. Вставить ссылку на папку либо выбрать её доступным платформенным способом.
2. Проверить тип, аккаунт, права; показать найденное имя и краткий план переноса.
3. **Автоматически созданные конфиги перенести как существующие файлы, сохранив fileId; прежние ссылки проверить после переноса.** Новые публикации направлять в новую папку.
4. **Индивидуально привязанные файлы оставить на своих местах**, сохранив назначения.
5. Не менять публичность молча. Проверить влияние наследуемых разрешений; невозможность сохранить выбранный доступ сообщать до эффекта.
6. Частичный перенос имеет сохраняемый журнал, количество оставшихся файлов и продолжение. Успех не показывается до проверки файлов и ссылок.

Реестр координатора P5 связан с folderId. Простая замена этого поля недопустима: нужна согласованная миграция авторитетного реестра, приостановка конкурирующих публикаций и защита от повторного создания файлов старым исполнителем. Смешанные версии должны останавливаться с понятным требованием обновления. Переезд согласуется между устройствами и переживает смену аккаунта/offline/restart без потери назначений.

### Индивидуальный файл клиента

Путь: **детали клиента → Файл конфигурации → Привязать по ссылке**.

1. Принять ссылку Drive на существующий файл или ID; учесть resource key при наличии.
2. Проверить тип, право изменения аккаунта, отдельное OAuth-разрешение приложению и отсутствие назначения другому клиенту. Уникальность действует на общий workspace, включая одновременные привязки с двух устройств.
3. Показать имя и доступный по запросу просмотр содержимого. **Первая перезапись требует одного явного подтверждения для проверенного файла и ревизии.**
4. Сохранить назначение; дальнейшие обновления автоматически пишутся в тот же fileId.
5. При перепривязке старый файл автоматически не удаляется, credentials не меняются. Индивидуальный файл имеет приоритет над общей папкой.
6. Проверить YAML и, для политики доступа по ссылке, скачивание без авторизации; только затем обновлять результат выдачи/QR.

Вставка URL не выдаёт права при scope `drive.file`. При недостатке разрешений нужен поддержанный выбор/предоставление доступа; scope молча не расширять. До успешной проверки нового назначения сохранять прежнее рабочее. Папки, shortcuts и Google Docs не принимать за обычный YAML без проверки типа/конечного файла.

## 7. Автоматизация

| Операция | Поведение |
| --- | --- |
| Синхронизация | Автоматически после изменений и при работе приложения |
| Генерация/публикация YAML | Автоматически после изменения профиля/подтверждённых доступов, по назначению и политике |
| Подготовка серверного плана | Из сценария редактирования; одно «Применить» |
| Проверка релизов | Автоматически с настройками отключения; ручной запуск в меню |
| Параметры протокола | Каталог адресов, свободный порт, SNI из Target, ключи при создании; ручное переопределение в дополнительных параметрах |
| Установка/обновление ПО и доступы | Подтверждённый план, проверки ревизий и защита от повторов |
| APT | Ручные проверка индексов и применение плана |
| Продление ACME | Существующий серверный механизм; без повторного выпуска при каждом редактировании |

Текущие синхронизация/публикация работают при открытом приложении. Работа при полностью закрытом Android этой спецификацией не реализуется. Серверные задания и продление сертификатов имеют собственный жизненный цикл.

## 8. Material 3 и доступность

- Развивать `packages/design_system`, `AppTheme`, `AppLayout`, `AppMotion`, не размножать локальные цвета/размеры по экранам.
- `ColorScheme`, типографика темы, общий seed при отсутствии dynamic color; светлая, тёмная и системная темы.
- Один уровень тональных поверхностей, простые строки/разделители вместо вложенных контурных карточек.
- `TabBar` — разделы сервера. `SegmentedButton` — короткие наборы настроек; при длинных переводах/крупном тексте доступный список выбора. `ChoiceChip` допустим для фильтров и сам по себе не нарушает M3.
- FAB не обязателен. В каталогах согласован один «+» в шапке; плавающей копии нет.
- Длинные формы на телефоне — отдельный экран/полноэкранный диалог. Короткие действия — sheet/диалог по доступному месту.
- Touch targets не менее 48×48, клавиатура, focus/hover/pressed/disabled, screen reader, контраст. Цвет не является единственным признаком статуса.
- Единый motion с системным reduced motion, без декоративных бесконечных анимаций и повторного исполнения команд при переходах.
- Все продуктовые строки/состояния — RU/EN. Русский HTML-макет не доказывает локализацию или Flutter accessibility.

## 9. Состояние реализации и стадии

Уже есть: общий Flutter M3 theme/motion, каталоги, выдача YAML, базовый профиль в настройках, автосинхронизация, проверка релизов, автоматические публикации P5. Templates уже удалён, диагностика сервера частично свёрнута. Повторно реализовывать эти результаты не нужно.

В текущей Flutter-стадии реализованы три постоянных раздела без P0-обзора, компактные каталоги, вкладки сервера, группы настроек, окно выдачи с QR и копированием нажатием. Перенос всех длинных форм в полноэкранный режим, совместное представление списка/деталей на широком экране и полная приёмка доступности ещё не завершены; P1-08 целиком не закрыт.

Предстоят новые операции: удаление клиента с отзывом, перенос папки/реестра, индивидуальные файлы. `PublicationController.configure()` пока запрещает повторную настройку, необходимые move/delete/bind операции не представлены полностью в контрактах. Они согласованы как требования и не выдаются за результат этой UI-стадии.

Прежнее ограничение «только UI, контроллеры без изменений» отменяется: новые функции требуют прикладных/доменных изменений и миграций. Сохраняются защита секретов, стабильные credentials, ревизии, causal merge, tombstones и единственность внешних эффектов.

| Часть | Результат | Состояние |
| --- | --- | --- |
| UI-1 | Три раздела, общий layout/theme, компактные каталоги/настройки, вкладки сервера | Реализовано; полная адаптивная/ручная приёмка остаётся |
| UI-2 | Окно выдачи, настоящий QR прямой ссылки, копирование нажатием, состояния публикации | Реализовано; системный clipboard и камера на устройствах требуют runtime-проверки |
| CLIENT-DELETE | Постоянное намерение, отзыв на нескольких серверах, offline/restart/sync, опциональная очистка Drive | Реализовано; [отчёт](reports/2026-09-15-client-deletion.md). Реальный VPS/Drive/runtime не проверены |
| DRIVE-FOLDER | Миграция реестра/файлов, сохранение ссылок/индивидуальных назначений, recovery и несколько устройств | Предстоит |
| DRIVE-BIND | Разрешения существующего файла, preview/подтверждение, уникальность, проверка перезаписи/ссылки | Предстоит |

Следующий конкретный пункт согласовать отдельно. Для Flutter-стадий — применимые widget/интеграционные проверки, analyze/verify, Linux/Android сборки с Google-настройкой. Для внешних операций — отдельно согласованный синтетический стенд. Рабочие файлы владельца не использовать для тестовых мутаций. Windows, реальные устройства, QR-сканирование и runtime фиксировать отдельно от сборки/HTML.

## 10. Критерии приёмки реализации

1. Три раздела на compact/medium/expanded; детали не остаются поверх другого раздела.
2. Нет P0-обзора, постоянных технических сводок, дублей создания/удаления/копирования ссылки.
3. Крупный текст, RU/EN, клавиатура, обе темы и reduced motion сохраняют действия и черновики.
4. QR сканируется в тот же URL, который копируется; успешный snackbar только после успешного clipboard API. Отказ API виден.
5. Приватный/непроверенный URL не выдаётся за подписку; ошибка не заменяет последнюю рабочую публикацию.
6. Удаление переживает offline/restart/sync, прекращает выдачу, отзывает управляемые доступы и не воскрешается старой копией.
7. Перенос сохраняет fileId и проверяет старые ссылки; индивидуальные файлы остаются на местах; частичный сбой не теряет назначения.
8. Привязка проверяет OAuth/права/уникальность и подтверждает первую замену, не удаляет старый файл и не меняет credentials.
9. Sync/restart/два устройства не создают второй upload/перенос/удаление/runner submit.
10. Отчёт каждой стадии различает реализацию, сборки, mocks и фактические внешние проверки.
