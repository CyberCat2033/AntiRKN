# Диагностика IP

Актуальный интерфейс по уточнению владельца от 2026-09-17: одна большая кнопка в «О сервере» → окно выбора TCP :443 или SSH на сохранённом SSH-порту → результаты под IPv4 в том же списке. Проверяются все публичные IPv4 текущего сервера (до 64); ручного выбора адреса/порта, отдельной вкладки и кнопок в строках IP нет. IPv6 остаются видимыми в сведениях сервера, но целевые и контрольные IPv6-пробы не запускаются. TLS/SNI и подробный отчёт убраны из интерфейса.

Алгоритм от 2026-09-16 сохранён: проверка с устройства, после неудачного соединения сравнивается доступность контрольных адресов; 9 доступных из 10 — нормальный результат. Запуск только вручную, после выбора метода и нажатия «Начать проверку» в том же окне. SSH проверяет banner без входа. ICMP не используется.

## Последовательность

1. При текущих операциях с сервером/профилями/обновлениями запуск отклоняется. Приложение закрывает свободные SSH-соединения, приостанавливает Google sync, публикации, reconcile и проверку обновлений. Другие приложения и оборудование не контролируются.
2. Фиксируется сеть/маршрут. Для каждого используемого семейства адресов строится собственная исходная оценка: два прохода по контролям, максимум четыре одновременных соединения, общий таймаут каждой пробы 3 с. Все проверяемые IP исключаются из контролей. Достаточно не менее 8 стабильных адресов, 4 операторов и 70% исходного списка. Без такой базы целевые IP этого семейства не проверяются.
3. Цели обрабатываются последовательно. Успешное соединение — переход к следующему IP. Неуспешное — проверка только стабильно доступных контролей того же семейства. Доступность не ниже 90% нормальна (9/10, 13/14); одна неудачная контрольная точка не означает сильную блокировку.
4. При ухудшении контрольная проверка повторяется. Признаки сильной блокировки: в обеих проверках доступно не более половины контролей и потеряны адреса не менее трёх операторов; либо недоступны все стабильные зарубежные Atlas-контроли минимум двух операторов, а российский Atlas-контроль доступен. Промежуточная деградация также останавливает очередь, но без признака сильной блокировки.
5. Остановленная очередь автоматически не продолжается. Около трёх минут проверяются только контроли с интервалами 10–30 с, подозрительный IP повторно не затрагивается. Последняя начатая серия может завершиться до 12 с после окна наблюдения. Фиксируются восстановление и длительность от подтверждения ухудшения. Нормальный результат повторной проверки до начала наблюдения позволяет продолжить исходную очередь.
6. Смена сети/маршрута делает результат неполным. Большая кнопка «Остановить», Back во время работы или уход в фон закрывают диагностические сокеты; возвращение в приложение не возобновляет тест. SSH автоматически обратно не подключается; обычные фоновые очереди приложения выходят из паузы.

## Контрольные точки версии 1

Состав сверён по документации операторов и RIPE Atlas API 2026-09-16. Это кандидаты, а не обещание постоянной доступности. У DNS-операторов проверяется только TCP handshake на порту 53, без рекурсивных запросов; Atlas — HTTP `GET /0` на порту 80 с ожидаемым статусом 200. Режим HTTP внутренний, для контролей. ## Платформы и ограничения результата

Android использует socket factory активного `Network` и сверяет identity между сериями; процесс целиком к сети не привязывается, активный VPN не обходится. [Android Network](https://developer.android.com/reference/android/net/Network). Linux использует системный маршрут, проверяет интерфейсы, таблицы и правила IPv4/IPv6 через iproute2; Windows — интерфейсы и `route PRINT`. На desktop сокеты не закрепляются за адаптером. Обозначение VPN на desktop эвристическое, по имени интерфейса. Отсутствие необходимых сведений о сети не подменяется успешной диагностикой.

Результат относится к одному устройству, времени, семейству адресов, порту и способу проверки. Закрытый порт, неработающий сервер, TLS-сертификат, фильтрация DNS-порта, потери маршрута и внешняя активность могут влиять на него. Наличие соединения не обещает доступность всех протоколов; массовый обрыв — диагностический признак, не доказательство действия РКН. [OONI о неоднозначности сетевых аномалий](https://ooni.org/support/faq/).

Последние пять запусков сохраняются в локальных settings: цели, статусы, измеренное время, этапы контрольных проб и итог. До 512 образцов на запуск, при переполнении сохраняются целевые результаты, число отброшенных контролей явно указано. Снимки пишутся при смене этапа и продвижении очереди; незавершённый запуск после перезапуска помечается прерванным. История содержит IP/порты/SNI, но не идентификатор Android Network, локальные интерфейсы или credentials. В интерфейсе отображается только последний результат соответствующего сервера под каждым проверяемым IPv4. Запуски привязаны к ID сервера, host, сохранённому SSH-порту и fingerprint host key; старые несвязанные отчёты не подставляются. Просмотр отдельной истории, копирование JSON и очистка убраны. Журнал не отправляется в публичную диагностику; он может входить в обычную локальную резервную копию settings.
